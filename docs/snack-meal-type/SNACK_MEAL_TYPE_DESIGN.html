Snack as a fourth meal type

Design only. Nothing in the app or backend is changed by this page. It settles what Snack is, where it shows, and what it must never do, before any screen is written.

2026-11-16, revised the same day after the user's screenshots · meal planning redesign, task m4-09 · must land before m5-04 (the planner's snack slot)

1Why now

m4-05 gave the day a 25 / 30 / 35 / 10 split, and the 10% is the snack: about one fruit and one dairy serve, roughly 215 kcal on a 2,150 kcal day. m5-04 will start suggesting snacks. If a user can't log a suggested snack anywhere, the planner can't tell whether they ate it.

The database is already ready: meal_logs.meal_type is plain text, not an enum, and the save route does not check it. No database change is needed. All the work is in code that assumes there are only three meals.

2The trap this has to avoid

A snack logged today would count, but appear nowhere The backend adds every log for the date to the day's total (routes/meals.js, the add-meal response). But Meal Summary only lists rows whose type is exactly breakfast, lunch or dinner (meal/summary.tsx lines 317–319). A snack would push the day's total up, appear in no list, and have no row with a delete button. The user would see a total that doesn't add up, with no way to fix it.

The same silent filter exists in four backend places: recent meals (meals.js line 358), meal-pattern insights (calorieInsights.js), most-consumed (mostConsumedMeals.js) and the recommendation builder. Each has its own copy of the three-item list.

So the rule for the build: one shared list of meal types in each repo, and every screen and service reads from it. That's 9 separate copies in the app and 6 in the backend today. Adding Snack to one shared list, instead of patching each copy, means a fifth type later is one edit, not twenty.

Order of the build: backend first (it already stores snacks; it must also return them), then the app. An app build that predates this will still hide snacks. That only matters if the same person logs on two devices with different builds, which is acceptable for the test group.

"No reminder, ever" matters most here. A snack nudge from a health app reads as "you should eat more". That's the wrong message for someone trying to lose weight, and Pip's tone is built on never making logging feel like a scorecard.

5Decisions

All four taken by the user on 2026-11-16: the recommended option in each case.

D1 · Where Snack sits in every list
Decided: last, after Dinner. A snack can happen at any time, so putting it between two meals would suggest it belongs to the afternoon. Last also matches the backend's split order (breakfast, lunch, dinner, snack).
Other option: between Lunch and Dinner, where an afternoon snack would fall in time.
D2 · Does the app ever pre-select Snack?
Decided: never. The time-of-day default stays as it is (before 11:00 Breakfast, before 17:00 Lunch, otherwise Dinner). Snack is always a choice the user makes, so a late lunch logged at 15:30 isn't quietly filed as a snack.
Other option: 15:00–17:00 and after 21:00 default to Snack.
D3 · Colour and icon
Decided: green #15803D with the apple icon (Ionicons nutrition). Each existing meal has its own colour (blue, orange, dark grey), and green is the only one left that doesn't look like an error. White text on it has a 5:1 contrast, so the header stays readable.
Other option: a lighter teal, or reuse the orange of Lunch.
D4 · Insights (Calorie Summary's meal pattern)
Decided: Snack becomes a fourth slot, and a day without one is never counted as a gap. "You snack about 900 kJ a day" is useful; "you skipped your snack on 4 days" is not.
Other option: leave insights at three meals for now.

7Not in this task

  • The planner suggesting snacks: m5-04. Rule fixed now so it is not lost: the planner only ever suggests snacks from the five food groups (fruit, yoghurt, milk, cheese, vegetables, wholegrain crackers, nuts) and never discretionary foods (cakes, sweet biscuits, chocolate, chips). Source: Eat for Health, "Swap discretionary snacks for snacks from the five food groups". A user can still LOG a slice of cake as a snack; the log is an honest record.
  • Drinks as their own slot (water, the 2.6 / 2.1 L target): m5-04, design later.
  • Alcohol: logged under whichever meal the user picks; counting it is m4-10.
